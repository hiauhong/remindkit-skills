# gtd · 承诺循环

面向 Apple Reminders 的个人承诺执行方法论。数据全在 Reminders（通过 remindkit 读写），本 skill 只定义**流程与标准**，不定义数据结构。

**核心哲学**：用户只做三件事 —— 记录（随手）、审批（两键）、执行（做那几件）。其余认知劳动（体检、厘清、精选、复盘、迁移）全部由 agent 承担。

## 当前时间（不要猜，用这些值）

- 今天 (ISO)：!`date +"%Y-%m-%d"`
- 现在 (本地)：!`date +"%H:%M %Z"`

## 承诺循环五环

```
① 捕获 → ② 体检 → ③ 聚焦 → ④ 执行 → ⑤ 复盘 → ⑥ 迁移（每月）
```

每次会话先明确用户处于哪一环。默认入口是 ② 体检（任务库先健康，规划才成立）。

---

## ① 捕获（零承诺记录）

**原则**：什么都能记，零承诺。"某天/也许"的事也允许记录，agent 不精选、不催，只在复盘时扫一遍。

- 收件箱列表：用户已有约定（如某个 inbox 列表），新想法先落这里
- 记录动作直接用 remindkit 写命令（`add`），无需分析合理性 —— 体检环负责纠偏

## ② 体检（任务健康检查）

**任务库先健康，规划才成立。** 基于全量任务做语义检测，输出报告 + 纠正提案，用户两键裁决后才进入规划。

### 检测标准

| 维度 | 判断标准 | 实例（不合格） |
|---|---|---|
| 无行动出口 | 任务是愿望/目标，没有可执行的下一步动作（无子任务且标题不可直接执行） | 「学英语」「练字」「多读书」 |
| 缺 KR | 目标是"结果型"（可量化/有 deadline）但没有可衡量的关键结果（KR 为 OKR 术语；若用户不以 OKR 组织，退化为"缺可衡量里程碑"） | 「保持健康」无 KR |
| 重复 | 标题或语义近似的条目重复存在 | 「每周复盘」出现 2 次 |
| 僵尸 | 长期未完成且无近期活动（阈值默认 30 天，可问用户） | 「每天阅读」躺了 6 周 |
| 无日期 | 无 dueDate，永远进不了每日计划（确认是否"某天"性质） | 50 条里 12 条无日期 |
| 归属错误 | 列表角色与事项性质不匹配（目标混在收件箱 / 行动项放目标列表 / 某天性质却设紧急截止） | 「学英语」放在「收件箱」而不是「目标」 |

### 检测流程

1. `remindkit dump` 或定向查询拿数据（优先 `--fields id,title,completed,dueDate,subtaskIds,section` 省 token）
2. 逐维度检测，区分**机械项**（无日期/过期/字符串重复 —— 用查询命令直接得出）与**语义项**（无行动出口/缺 KR/近义重复 —— agent 判断）
3. 输出报告：每个维度 = 数量 + 条目列表 + 建议修复动作；另含 **💡 建议新增** 类别 —— agent 补充用户没想到的有价值事项（缺的 KR、该跟进的下一个动作、被忽略的领域）
4. 用户裁决（每个维度单独确认）：修复 / 忽略 / 稍后（建议新增：接受 → `add` / 打回 → 丢弃）
5. 修复动作调用 remindkit 写命令：`update`（补日期/补KR备注）、`move`（归位）、`delete`（杀僵尸）、`add`（补子任务）等

### 输出格式

```
体检报告
├── ⚠ 无行动出口  5 条    [修复/忽略/稍后]
│   学英语 · 练字 · 多读书 · 整理衣柜 · 学做饭
├── ⚠ 缺 KR      3 条    [修复/忽略/稍后]
│   保持健康 → 建议KR: 每周运动 3 次
├── ⚠ 重复       2 对    [修复/忽略/稍后]
│   每周复盘 ×2
├── ⚠ 僵尸       4 条    [修复/忽略/稍后]
│   每天阅读（30天未动）
├── ⚠ 归属错误   2 条    [修复/忽略/稍后]
│   「学英语」在「收件箱」→ 建议移到「目标」
└── 💡 建议新增   1 条    [接受/打回]
│   保持健康 → 补 KR: 每周运动 3 次（未拆出）
```

**裁决是必须的**：修复建议 agent 提案，是否执行只有用户能定 —— "学英语"该补 KR 还是降级某天，只有用户知道意图。

## ③ 聚焦（每日精选）

### ROI 精选算法

对每个候选任务做 ROI 初判（高/中/低），再按以下规则选择：

```
每日精选 = ROI 初判 × 精力匹配 × 截止约束 × 第二象限保护
           WIP 上限 3~5 件 + 1 件 Highlight
           用户两键审批 = ROI 的最终裁决
```

- **ROI 初判**：高（杠杆/复利：推进长期目标、一次投入长期受益）/ 中（日常）/ 低（开销：回复、琐事）
- **第二象限保护**：每天至少 1 件"重要不紧急"（学习、锻炼、长期项目），否则永远被挤掉
- **Highlight**：今天最重要的一件 —— 排第二（启动小事之后），趁动量做
- **执行顺序**：启动小事（2 分钟）→ Highlight（趁动量）→ 收尾
- **反 Goodhart**：绝不用"完成数量"作为成就指标展示；突出 Highlight，弱化完成数

### 长期关注清单（周 / 月）

每日精选管短期，长期靠定期输出：基于健康任务库，agent 生成一份**长期关注清单** —— 目标进度（若用户以 OKR 组织则含 KR 完成度）、被忽略的领域、下一个大动作、该转正或转灭的「某天/也许」项。走同一条两键审批，是复盘环（⑤）的固定出口。

### 拆解粒度

大任务拆成 1~2 个番茄钟（25~50 分钟）能干完的子任务，用 `add --parent` 挂到父任务下。

## ④ 执行（用户）

- 用户执行被精选的任务；agent 提供启动助推（第一件 2 分钟小事）
- 完成后自动勾选（用户操作或用户让 agent `complete`）
- **不催、不罚**：未完成的滚入明天，复盘环校准

## ⑤ 复盘（每周回顾）

固定清单，agent 逐项执行，输出报告，用户审批：

1. **收件箱清零**：堆积超过阈值（如 5 条）→ 建议归位
2. **完成率**：本周完成 vs 计划 → 校准下周容量（完成率回填规划量）
3. **目标进度**：目标列表（如用户以 OKR 组织则为 OKR 列表）各目标完成度（已完成子任务/子任务总数）
4. **ROI 分布**：上周时间花在哪些杠杆等级 → 建议砍 Overhead
5. **某天/也许**：扫一遍长期关注，决定是否转正
6. **等待清单**：Waiting For 类任务是否该跟进
7. **建议新增**：补齐用户没想到的有价值事项（缺的 KR / 该跟进的下一个动作）→ 接受后 `add`

## ⑥ 迁移（每月检视）

未完成任务不是无限顺延：

- agent 列出"该杀掉/降级"的候选（连续多周未动、已无意义）
- 用户裁决：继续 / 杀掉（`delete`）/ 推迟（`update` 改日期或移到某天列表）
- **防止任务僵尸化** —— 任务系统反脆弱的关键

---

## 用户约定

- 用户的列表结构以 `list --format json` 的 note/role 为准（列表用途以 note 备注为准）
- 角色定义（目标/收件箱/普通）由 remindkit-scope 前端管理，agent 会话中以询问或 `list` 输出为准
- 任何写操作前先确认（用户裁决），不擅自修改用户数据

## Token 效率

- 优先定向查询（`count` / `today` / `overdue` / `query`），全量 `dump` 谨慎
- 一律 `--fields` 投影；多个查询用 `;` 串在同一个 Bash 调用
- 机械检测优先用查询命令得出，语义检测再基于最小数据子集
