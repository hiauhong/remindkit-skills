# okr · 目标管理（可选方法论）

面向 Apple Reminders 的 OKR 目标管理协议。**可选方法论**：承诺循环（gtd skill）不假设用户用 OKR；只有用户以 OKR 组织目标时才启用本 skill。

## 结构映射（Reminders ↔ OKR）

```
Apple Reminders                 OKR 概念
────────────────────────────────────────────────
列表（角色: 目标）               OKR 库
分区 section（领域）             组织维度（可选：工作/健康/财务…）
任务 task                        O 目标（方向，可挑战）
子任务 subtask                   KR 关键结果（可量化、有 deadline）
KR 的子任务                      Action 行动/下一步（衔接 gtd 无行动出口）
```

- 拿到结构优先用 `remindkit list --format json`（含 note 备注）+ `query --list <目标列表> --tree`（看父子层级）
- 角色认定以列表 note 为准；用户不用 OKR 结构时，本 skill 不适用

## 目标体检（季度/年度）

四个维度，agent 语义检测，用户裁决：

| 维度 | 判断标准 | 实例（不合格） |
|---|---|---|
| O 是行动而非方向 | O 表述为具体行动/习惯，没有"方向"张力（真正的 O 是挑战性目标） | 「每天出门拍照」→ 更像 KR，O 应为「建立个人摄影作品集」 |
| KR 不可量化 | KR 无数字/无 deadline，无法判断达成与否 | 「提高摄影水平」→ 建议 KR「每月完成一组主题拍摄」 |
| KR 缺行动支撑 | KR 无子任务且不可直接执行（下一步未知） | 「学人像摄影」→ 拆「周末约拍一次人像」 |
| O/KR 层级错乱 | 目标平铺、O 与 KR 分家（父子关系丢失） | 「掌握摄影」与其 KR「学构图」「练人像」分家 → 挂父子 |

流程：

1. `query --list <目标列表> --tree` 拿层级
2. 逐维度检测，输出报告（格式见下）
3. 用户裁决：修复 / 忽略（写操作先确认，走 remindkit `update` / `move` / `add --parent`）

### 输出格式

```
目标体检报告
├── 🎯 目标 8 个（分区按用户领域，如 职业 / 健康 / 财务）
├── ⚠ O 是行动而非方向  2 个    [修复/忽略]
│   「每天出门拍照」→ 建议 O: 建立个人摄影作品集（KR 化）
├── ⚠ KR 不可量化       3 个    [修复/忽略]
│   「提高摄影水平」→ 建议 KR: 每月完成一组主题拍摄
├── ⚠ KR 缺行动支撑      4 个    [修复/忽略]
│   「学人像摄影」→ 补子任务: 周末约拍一次人像
└── ⚠ O/KR 层级错乱     2 个    [修复/忽略]
│   「掌握摄影」↔「学构图」「练人像」→ 建议挂父子
```

## 进度追踪（周/月，配合 gtd 复盘）

- KR 完成度 = 已完成行动 / 总行动（`query --tree` + completed 统计）
- O 进度 = 各 KR 完成度的简单平均（加权可选）
- 输出每个目标一行：`O | 进度 % | KR 列表 | 卡点`

## 季度检视（F6 行动出口）

每个 O 三选一：**继续 / 调整 / 放弃**，用户裁决后：

- 继续 → 保留；调整 → `update` 改 KR/deadline；放弃 → `delete`（软删）
- 目标层不是"计划好了就完"，定期检视防止僵尸目标

## 与承诺循环的衔接

- gtd skill ②体检的「缺 KR」维度：KR 为 OKR 术语；用户用 OKR 时按本 skill 标准执行，不用则退化为「缺可衡量里程碑」
- gtd skill ⑤复盘的「目标进度」：按本 skill 的进度追踪计算
- 本 skill 不定义承诺循环本身；承诺循环始终由 gtd skill 承载

## 用户约定

- 目标列表名以 `list --format json` 的 note 角色为准（如「OKR」「目标」）
- 所有写操作前先确认；不擅自改用户目标
- 同名列表重复时用 UUID 精确定位
